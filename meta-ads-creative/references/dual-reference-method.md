# dual-reference 方式（参照画像2枚で「ブランド一貫 × 写実UI」を両立）

## なぜこの方式か

AIに広告画像を1枚のプロンプトだけで作らせると、だいたいこのどちらかで失敗します。

- **UIが安っぽい / イラスト調**になり、プロのSaaS広告に見えない
- **ブランドのキャラ（マスコット・ロゴ）が毎回別物**になり、世界観が崩れる

これを解決するのが「**参照画像を2枚同時に渡す**」方式です。画像生成（編集）APIは、渡した参照画像のスタイルを継承します。そこで役割の違う2枚を渡します。

## 2枚の役割

### 参照1：ブランドキャラ / ロゴ（固定で毎回渡す）
あなたのマスコット・キャラクター・ロゴの画像。これを毎回渡すことで、生成される広告内のキャラが**いつも同じ見た目**になります。
- 背景透過 or 単色背景の**クリーンな素材**を用意する（余計な装飾が写り込むと崩れる）
- `config.md` の `brand_character_image` にパスを登録

### 参照2：構図・品質のお手本（訴求ごとに切替）
**photo-realistic で品質の高いSaaS広告/UIモック**を1枚。これを渡すと、生成されるUIの作り込み（影・グラデ・余白）がこのレベルに引き上がります。
- 自社の過去の良いクリエ、または品質の高い参考広告の構図
- 訴求・構図に合うものを選ぶ（比較訴求なら左右分割の見本、など）
- `config.md` の `composition_references` に訴求別で登録

## 肝：2つのスタイルの「共存」を明示する

プロンプトで必ず、**この2枚が別々の役割であること**を言葉で指定します。

> 「2つのスタイルを共存させる：**UIは写実的なSaaSモック**、**キャラはイラスト**」

そして Avoid 句に「**UIをイラスト調にしない**」「**キャラを写実にしない**」の両方を入れます。これを書かないと、AIが片方に引っ張られて崩れます。

## 仕上がりの目安

- ヘッドラインが大きい（画面の上 1/4 くらいを占める）、強調キーワードだけ**ブランドの差し色**
- UIに具体的な体験が描かれている（ユーザーの問い → 製品の答え → 次の行動）
- ブランドキャラは隅に小さく（例：右下）、世界観のアクセントとして
- CTA（ボタン）が下部中央に、行動を促す形で
- 1枚＝1メッセージ。視線が「見出し → ビジュアル → CTA」で流れる

## よくある失敗（先回り）

- 参照画像なしで生成 → キャラが別物・UIが安っぽい（**必ず2枚渡す**）
- 参照1に装飾の多い画像を使う → キャラが崩れる（クリーン素材を使う）
- 1枚に訴求を詰め込む → 何も伝わらない（1画像1メッセージ）
- 実在ブランドのロゴ（連携先など）をそのまま描かせる → 崩れる/権利問題（一般化したラベルにする）
- テキスト、特に日本語が崩れる → 文字数を絞る・品質設定を上げる・作り直す
