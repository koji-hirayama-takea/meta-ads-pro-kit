# 画像生成のバックエンド（Codex デフォルト / API は量産用）

広告画像をどこで生成するか。2通りあります。**まずは Codex を試し、量産・最終品質で API を使う**のがおすすめです。

> 🚨 課金が発生する生成（API）は、実行前に必ずユーザーに確認すること。

## ① Codex CLI 経由（デフォルト・追加API課金なし）

ChatGPT のサブスク（Plus / Pro）に入っていれば、**Codex CLI の画像生成はサブスク枠内で使えます**（画像1枚ごとの API 課金が発生しない）。試行錯誤や1枚ものに向きます。

- 前提：Codex CLI をインストール済み + ChatGPT サブスク
- 使い方：Codex に「この訴求・このブランド素材で、1080×1080 のMeta広告画像を作って」と依頼。参照画像（ブランドキャラ）も渡す
- 長所：**追加課金なし**、手軽
- 短所：参照2枚を厳密に効かせる制御は API ほど効かない場合がある。最終品質はAPIに分がある
- 「無料で動かす」を重視するなら、まずこれで十分

## ② gpt-image-2 API（量産・最終品質・従量課金）

dual-reference（参照2枚）を最も効かせられるのがこちら。本番入稿用や量産に向きます。

- 前提：OpenAI の API キー
- 課金：1枚あたり概ね $0.05〜0.08（枚数ぶん。**事前にユーザー承認**）
- 特徴：画像「編集（edits）」モードで参照画像のスタイルを継承。UIの作り込みとキャラ一貫性が最も安定
- 時間：1枚あたり数分かかることがある。タイムアウトはリトライ前提
- 自前スクリプトや既存の画像生成ツールから、参照画像を2枚渡して呼ぶ

## どちらを使うか

- **試す / 1〜数枚 / コストをかけたくない** → ① Codex
- **量産 / 最終入稿品質 / 参照を厳密に効かせたい** → ② gpt-image-2 API

どちらで作っても、できた画像の**入稿は meta-ads MCP**（`upload_ad_image` → `create_ad_creative`）で行います。このスキルは「画像を作る」まで、配信に乗せるのは MCP の役割です。
