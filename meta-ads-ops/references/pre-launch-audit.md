# 配信前監査チェックリスト

新規 / 変更した campaign・adset・ad を **PAUSED → ACTIVE にする前に必ず通す**。
`meta-ads` MCP で現設定を取得し、各項目を突き合わせ、未解決があれば NO-GO。

## STEP 1: 現設定を取得

`meta-ads` MCP の `get_campaigns` / `get_adsets` / `get_ads` / `get_account_pages` で、
対象の campaign・adset・ad・アカウント基本情報を取得する。

## STEP 2: チェックリスト

### キャンペーン レベル
- [ ] **目的（objective）** が、本当に取りたい成果と一致しているか（例：リード獲得なら OUTCOME_LEADS）
- [ ] **予算の置き場所**（キャンペーン側 = CBO か、広告セット側 = ABO か）が意図通りで、二重設定になっていないか
- [ ] **特別広告カテゴリ**（信用・雇用・住宅・政治など）の指定が正しいか（該当しないなら空でも明示的に確認）
- [ ] status が PAUSED で作成されているか（いきなり ACTIVE になっていないか）

### 広告セット レベル
- [ ] **最適化目標（optimization goal）** が、キャンペーン目的と矛盾していないか
- [ ] **コンバージョンイベント** が正しく指定され、そのイベントが実際に発火する状態か（STEP 3 で実機確認）
- [ ] **言語 / 地域 / 年齢** などのターゲティングが、思い込みでなく **API 検証済みの値** で入っているか
      （言語コード・地域ID・interest ID は `search_*` ツールで実際の意味を確認してから入れる）
- [ ] **配信面（placements）** が意図通りか。自動配置だと低品質面まで含まれることがあるので、初期は絞っているか
- [ ] **自動オーディエンス拡張** の ON/OFF が、データ量・段階に対して適切か（初期は OFF が無難）
- [ ] **入札戦略** が段階に合っているか（初期は「最低コスト」で学習、安定後に目標CPAへ。`config.md` の方針に従う）
- [ ] **アトリビューション設定** が最適化目標と整合しているか（作成後は変更不可なので慎重に）

### アカウント レベル
- [ ] アカウントが停止 / 支払いエラーになっていないか
- [ ] 残高 / 支払い方法が有効か
- [ ] 計測（ピクセル / CAPI）が接続されているか

## STEP 3: 実機確認（API だけで終わらせない）

- [ ] **計測イベントが実際に発火するか**：本番フローを1回踏んで、コンバージョンイベントが記録されるか確認する。
      ここが死んでいると、AI（Meta の最適化）は何を学習していいか分からず、お金だけ溶ける。
- [ ] **API 設定と管理画面 UI の表示が一致するか**：API で入れた値が、Meta の管理画面で意図通りに表示されているか目視する。
      （特に言語・地域は、UI 表示で「意図した対象」になっているかを最終確認する）
- [ ] **広告の審査ステータス**：審査落ち / 審査中でないか。

## STEP 4: GO / NO-GO

- 未解決のチェックが **1つでもあれば NO-GO**。何が未解決かを列挙して人間に返す。
- すべてクリアしたら、危なかった点・前提を添えて GO を提示する。**ACTIVE 化の最終判断は人間が行う。**

## なぜこの監査が効くのか

事故の大半は「配信を始めてから気づく」もの。撒いてしまったお金は戻らない。
ONにする前に止まる習慣ひとつで、「気づいたら数日分の予算が無駄になっていた」をほぼ消せる。
