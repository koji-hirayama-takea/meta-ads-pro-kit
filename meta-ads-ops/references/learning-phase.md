# 学習フェーズ管理

Meta 広告は配信開始後に「学習」をする。誰に出せば成果が出るかを Meta 側が探る期間。
ここを理解せずにいじると、学習が振り出しに戻り、いつまでも成果が安定しない。
**素人とプロで一番差が出るのがここ。**

## 3つの状態

- **学習中（Active Learning）**：配信開始直後。成果は不安定で当たり前。**原則さわらない。**
- **学習限定（Learning Limited）**：成果数が足りず学習が完了できない状態。設定見直しのシグナル（予算が小さすぎる / オーディエンスが狭すぎる / CPA が高すぎる等）。
- **学習脱出（Outside Learning）**：学習が終わり安定運用に入った状態。ここで初めて本格的なスケール判断ができる。

## 学習をリセットしてしまう主な変更（要注意）

以下をやると学習がやり直しになる。**学習中は避ける。**

- 予算を大きく増減する（目安：±20% 超で要注意）
- 入札戦略を変える
- コンバージョンイベントの設定を変える（実質、広告セット作り直しに近い）
- クリエイティブを一気に大量入れ替える
- ターゲティングを大きく変える（地域・年齢・興味など）
- 配置（placements）を切り替える（手動 ↔ 自動など）

## 時間軸での動き方

- **Day 1〜3（Discovery）**：何があっても触らない。数字が悪く見えても、それは学習中だから。
- **Day 4〜7（Refinement）**：明らかに弱い広告だけ、慎重に手を入れる。大きな変更はしない。
- **Day 7〜14（Optimization）**：データが溜まったら、勝ち負けを見て最適化する。

## 立ち上げ初期（0→1）の現実

成果数が少ない初期は、学習の完了基準（一定数の最適化イベント）に届きにくい。
これはプロでも同じ。対策の型：

- **最終成果だけで最適化させない**。コンバージョン数が少ないうちは、その手前の動き（クリック / ランディングページ到達など、より発生しやすいイベント）も手がかりにして、いったん学習を進ませる。
- 成果が溜まってきたら、本来の最終コンバージョンへ最適化を寄せていく。
- 焦って予算やターゲットをいじらない。**「学習を稼ぐ」発想**を持つ。

## 「いじって大丈夫?」と聞かれたときの答え方

1. 対象 adset の配信開始からの経過日数と状態を確認する。
2. Day 1〜3 / 学習中なら → **「今は触らない方がいい」** と答え、理由（学習リセット）を添える。
3. どうしても変える必要があるなら → その変更が**リセット対象か**を判定し、リセットされるなら
   「ここまでの学習が無駄になる。やるなら覚悟の上で」と明示する。
4. 触っていい段階（学習脱出後）なら、何をどう変えるかを提案する。

## 出典の考え方

「7日で一定数の最適化イベント」という学習完了の考え方は Meta 公式の基準に基づく。
具体的な必要件数や自社の到達状況は、`config.md` と実データで確認すること。
