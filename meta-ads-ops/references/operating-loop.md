# 運用ループ（日次 / 週次 / 月次）

運用は身構えるほどのものではない。**見るタイミングと項目を固定する**だけ。
素人がやりがちなのは「毎日こまかく見て、毎日いじる」こと。これは学習リセットを自分で起こしているのと同じ。
**「見る」と「いじる」を分ける。**

## 🌅 日次（30秒、必要時のみ5分）

毎朝、次だけ確認する：
- 配信が**止まっていないか**（アカウント停止・支払いエラー・広告審査落ち）
- **異常な数値**が出ていないか（CPA 急騰 / 消化ゼロ / 予算の大幅超過 / 頻度が高すぎる）

問題なければ **触らない**。これが正解。
赤信号があったときだけ5分使って原因を切り分ける（多くは「学習中」か「計測が死んだ」か「審査落ち」）。

### 即対応すべきシグナル（例）
- アカウント / キャンペーンが停止
- 残高不足・支払いエラー
- 有効な広告セットがゼロ
- 直近の消化が急落（前日比で大きく減）
- CPA が基準線を大きく超えて高止まり

## 📅 週次（30分）

1週間分のデータで振り返る：
- 勝っている広告 / 負けている広告を **Scale / Watch / Kill** で分類する（decision-rules 参照）
- **必ずサンプル数の信頼度（low / medium / high）を添える**。数件で結論を出さない
- 疲弊兆候（頻度の上昇 + クリック率の低下）が出ていないか確認
- 来週の一手を1〜2個に絞る（あれもこれも変えない）

> 変更は週にまとめて、一度に。毎日ちょこちょこ変えない（学習リセット回避）。

## 📊 月次（60分）

大きな視点で：
- 今月の全体サマリー（消化・成果・CPA の推移）
- 効いた訴求 / 効かなかった訴求の整理
- 学び（想定外・失敗も含めて言語化）
- 来月の仮説（何を試すか）と、段階移行の判断（テスト → バリエ展開 → スケール）

## 避けるべきパターン

- 毎日数字を見て、毎日いじる → 学習が終わらない
- 数件のデータで「この広告は勝ち / 負け」と決める → 誤判定
- 複数の変更を同時にやる → 何が効いたか分からなくなる + 学習リセット
- 悪い数字を見て、学習中なのに焦って止める / 予算を変える

## 記録の習慣

変更したら **日時と理由**を残す。後から「なぜ良く / 悪くなったか」を辿れるようにする。
「数字が動いた理由を、説明できる状態を保つ」のが運用の質を決める。
